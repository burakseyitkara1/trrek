# Decision Log

Decisions made by the controller during development; each item says what was decided, why, and what it costs if it is wrong. New decisions are added at the end.

## Process

1. **A branch and PR per task, squash merge.** Because GitHub does not allow approving your own PR, "approval" is the independent reviewer's summary written as a PR comment, and the merge. Cost: none.
2. **`.superpowers/` is kept out of git** (`.git/info/exclude`). Tool files do not enter the repository. Cost: none.
3. **CI runs on the `macos-26-intel` image.** The macOS arm64 runners did not pick up the job in two attempts; the Intel image cross-compiles the app for arm64, and the Engine tests run on x86_64. Cost: CI does not run the arm64 binary (the engine is pure Swift, the risk is low).
4. **The packaging PR (#4) was merged with local verification.** Since CI could not run at all, `make check`, `make app`, `plutil -lint` and YAML parsing were relied on; the workflow was verified on a real runner in the next PR. Cost: a possible ci.yml error would have shown up one PR late.
5. **On Command Line Tools machines `make test` passes the Testing macro plugin path explicitly.** The new build system was skipping the plugin intermittently; machines with Xcode are not affected. Cost: none.
6. **Temporary branch chain.** Until CI reached main, task branches were derived from the previous task and rebased onto main after the merge. Cost: rebasing in order.
7. **Model choice by job.** Routine tasks a medium model, private API / concurrency / SwiftUI design a strong model; all reviews the strongest model. Cost: the risk of an extra fix round.

## Gesture engine

8. **0.001 mm tolerance in the step loop.** The Float rounding of normalized coordinates was missing exact multiples. Cost: a step 1/1000 mm early exactly at the boundary.
9. **The double tap window is measured from the lift of the first tap to the landing of the second.** The spec wording was ambiguous; lift→landing matches the user's perception. Cost: the window feels slightly longer.
10. **The engine owns its own lock** (`OSAllocatedUnfairLock`, every public call). Host signals made full state transitions, so the assumption that writing a flag was safe led to a race. Cost: nanoseconds per call.
11. **Clock contract: engine time = multitouch frame clock.** The frame clock is not the system uptime (a constant offset); `GesturePipeline.engineTime(fromUptime:)` learns the offset from the frames, returns `nil` before the first frame, and key events up to that moment are discarded. Cost: the typing gate is ineffective until the first frame.
12. **`bottomQuarterOnly` restricts only vertical edge slides; corners stay corners.** The check is done when the slide threshold is reached so that corner double taps are not cancelled by jitter. Cost: with the option on, top corner taps are preserved, a vertical slide cannot start from a top corner.
13. **`reset()` cancels** (`appSwitchCancel`/`scrubCancel`), `update(config:)` commits and drops the candidate. So that ⌘ does not stay held. Cost: none.
14. **`lastTap` is cleared on entering `spent`/`threeFinger`.** An intervening gesture does not count as a double tap. Cost: none.
15. **At most 64 steps per frame; the accumulation is reset when the limit is hit; a non-finite coordinate cancels the slide.** Corrupt data cannot lock up the engine or flood it with commands. Cost: none.

## Platform

16. **Path B (CoreBrightness + our own overlay) is primary for the keyboard backlight.** The HUD of the media key path could not be verified without permission. Cost: our own overlay instead of the system HUD.
17. **The cursor freeze tap is at the HID location** (`.cghidEventTap`). Movement swallowed at session level may not stop the cursor. Cost: none.
18. **The watchdog is set once at the start of the slide and re-arms itself for the remaining time** (re-arming on every frame did allocation); the time is computed only from the clock of the device driving the slide. Cost: an empty wake-up about every ~180 ms during an active slide.
19. **Haptic waveforms Light/Medium/Strong → 4/5/6**, a second pulse for Strong. The feel is left to the user's setting. Cost: none.
20. **`GesturePipeline.withEngine`** stays as a helper for access under the lock; it is no longer required since the engine owns its own lock. Cost: none.

## Release

21. **`TrrekVersion.string` is updated by hand in release PRs; the package version comes from the tag.** Cost: a mismatch visible only in "About".

## Final review

22. **Memory is measured as `phys_footprint`, not RSS.** RSS also counts shared system framework pages and exaggerates the app's own cost; the 15 MB budget applies to the footprint (note in spec 9.4). Cost: not directly comparable with the old RSS figures.
23. **A stable local signing identity ("trrek Local Signing").** An ad-hoc signature changes the code digest on every build and drops the Accessibility permission; a local identity keeps the permission. If signing with the identity fails (e.g. the keychain prompt was denied), the build falls back to ad-hoc with a warning. Cost: a one-time keychain prompt ("Always Allow") on the first signing.
24. **The `v0.1.0` tag is pushed only after the final review and the manual checklist are completed.** The tag triggers the release workflow; undoing it is expensive. Cost: the release is slightly delayed.
25. **Key event time = arrival time.** `InputMonitor` passes the `ProcessInfo.processInfo.systemUptime` value read inside the tap callback; since the clock of `CGEvent.timestamp` is not documented, it is not relied on (`TrrekProbe keys` prints both). Cost: the timestamp is late by the callback delay (under a millisecond), insignificant for the typing gate.
26. **Only trackpads produce gestures.** The kind is determined from the generic HID properties in the `AppleMultitouchDevice` record: a trackpad if `HIDPointerAccelerationType` = `HIDTrackpadAcceleration` or if `DeviceUsagePairs` contains Digitizer/Touch Pad (0x0D/0x05) usage; if one of the properties is present but there is no signal, it is not a trackpad (e.g. a mouse with a touch surface); if neither is present the device is used and a log is written. "Family ID" was not used: the values change with the hardware generation and there is no published list (the built-in trackpad here reports 110); an allow list would turn off the trackpad on new hardware. Devices are matched with the record entries through the multitouch ID. Cost: the classifier could not be verified by hand for a mouse; it was tested with representative dictionaries.
27. **Every action that sends synthetic events is off without permission.** All edges other than the keyboard backlight (which is set directly), all corners, middle click and cursor freeze are `.off`; the diagram shows the effective actions. Controls that looked on but did not work because events sent without permission are not delivered were misleading. Cost: until permission is granted trrek does almost nothing; the welcome window explains this on every launch.
28. **Reviewer claims are verified against the source; if wrong they are rejected with reasons.** A finding is fixed only once it is verified in the code or by measurement. Cost: the review round gets slightly longer.
29. **Cursor freeze is done by disconnecting the mouse from the cursor.** When a slide starts the position is saved and `CGAssociateMouseAndMouseCursorPosition(false)` is called; on release the connection is restored. The tap still swallows scrolling and, if the cursor happens to move, puts it back at the saved position. Merely swallowing the events did not stop the cursor (seen in manual testing). Cost: none.
30. **When switching to the stable signing identity the Accessibility record is reset once.** The old ad-hoc record does not match the new signature; the README explains this. Cost: the user re-grants the permission once at the switch.
31. **Releases are signed with Developer ID, notarized and published from the release Mac.** `scripts/release.sh` signs with the hardened runtime and a timestamp, notarizes and staples the app and the DMG, pushes the tag and creates the GitHub release. The certificate and notarization credentials are not uploaded to GitHub; the workflow triggered by the tag only verifies the build and tests. Cost: a release can be made only from that Mac.
32. **Local builds are also signed with the Developer ID identity first.** Since the local and published builds carry the same signing requirement, a single Accessibility permission is valid for both. Cost: the permission is reset once when the identity changes.
33. **Scrub Video is done by sending ←/→ arrow keys to the front app.** The first design in the spec envisioned getting around Apple's Now Playing access restriction with a helper loaded through the system interpreter; this conflicts with the hardened runtime/notarization and needs an extra process. Arrow keys are public, the permission already exists, and they work in browsers and most players. Cost: the step size is determined by the app (5 s in most), scrubbing works only in the front app; the overlay label assumes 5 s per step.
34. **External monitor brightness was added over DDC/CI as "best effort".** The packets are built from the VESA DDC/CI definition (source 0x51, 0x80 in the length byte, checksum is the XOR starting from the destination address 0x6E; the reply checksum starts from 0x50) and verified with pure tests. Services are taken from the external `DCPAVServiceProxy` entries in the IORegistry, matched to displays by EDID manufacturer/product/serial, and those that do not match are matched in order. Since I2C transfers need waiting (`usleep`), the dispatcher gives the DDC work to its own serial `DispatchQueue` and returns immediately; the overlay is updated from that queue. The maximum value is read once, the current value at the start of the slide (after a gap longer than 1.5 s). Steps that arrive while the queue is busy are merged into a single pending step per display and sensitivity (a fast slide does not lag, and does not continue in the old direction when the direction changes). After a failed transfer, the steps for that display return with "No DDC" without touching the bus until the next slide; at the start of the next slide the services are rescanned (at most once every 5 s). A display reconfiguration notification (plug, unplug, wake) also triggers a rescan; there is no timer. Since there is no external display on this Mac it could not be verified on hardware; `TrrekProbe ddc list` and the items in the manual test list (2.2a, 2.2b) are applied when an external monitor is found. Cost: monitors' DDC/CI implementations differ; on a monitor that does not support it or whose reply does not conform to the standard the overlay shows "No DDC"; the service–display matching is a heuristic that relies on registration order.
35. **Phase 2 final fixes.** When there is a label in the overlay (scrub time, "No DDC") the text takes its natural width and the level bar is hidden; for levels the percentage stays at a fixed width and the panel widens to 240×56 pt (width only), measured with a test where the widest texts fit. When the front app is trrek itself, scrub does not send arrow keys: the keys would have moved the pickers and lists in its own window. External displays for which no DDC service was found at all (wireless, virtual) are not considered external according to the last scan and use the media key path; a real I2C error on a display that has a service continues to show "No DDC". The scan is done in the background while it is being created and after a display reconfiguration. If the DDC symbols are missing the setting is disabled; the error is written to the log once on entering the error state. Cost: on the first step before the scan completes, a display without a service may show "No DDC" once; the panel widened by 20 pt.
36. **A single limit haptic at the end of the range, then silence (all level actions).** In manual testing, on the volume, brightness and keyboard backlight edges, after the limit was reached the haptic "clicks" continued as the slide continued and felt as if the level were increasing. `CommandDispatcher` now reads the level before a level step: the output volume with a public CoreAudio property (`kAudioHardwareServiceDeviceProperty_VirtualMainVolume`; unknown when muted or on a device without volume control), the built-in display brightness with `DisplayServicesGetBrightness` resolved with `dlsym` in `PrivateSymbols.swift` (no reader if the symbol is missing), the keyboard backlight with its own bridge. If the level is at the limit in the direction of the step (≥ 0.999 or ≤ 0.001) no key/step is sent; in the slide the first push to this limit plays a single `.limit` haptic, later ones play nothing, and the step haptic the engine sends afterwards is dropped. The limit state is reset when the direction changes, in a new slide (`.haptic(.start)`) and when commit/cancel/cursor release happens. Since the level of the external display is known only in the DDC queue, the limit haptic plays there, once per slide, with the first result at the limit (the haptic port is locked and thread-safe; it is called under the dispatcher lock); the display's last known level is cached and if the display is already at the limit the step haptic on the frame thread is dropped. Reading the level is per step, not per frame, and does no allocation. Cost: when the level is unknown (muted, no reader) the old behavior continues; the step that reaches the limit gives the normal step haptic, the limit haptic comes at the next push (on the external display both come together); one CoreAudio or brightness read is done on every step.

## 0.2.1 maintenance release

37. **Haptics play on the trackpad being slid on.** `DeviceHaptics` keeps an actuator for each stream device; the key is the device ID the engine gives with `CommandSink.handle(_:device:)` (`GesturePipeline.deviceID(of:)`, the bit pattern of the device reference). The actuator is opened from the multitouch ID. On an unknown device the built-in trackpad's actuator plays, and if that is missing, the system's generic haptic. The table is rebuilt every time the pipeline starts (launch, wake, device change); old actuators are closed after the change. The dispatcher keeps the device of the last command in its state, so the limit haptic in the DDC queue also goes to the right surface. Cost: on restart the actuators are reopened (milliseconds); the table lookup is one dictionary read per haptic, no allocation.
38. **Keyboard backlight level in a cache, writes on a serial queue.** The `TrrekProbe backlight bench` measurement (50 loops, debug build): read from the client + synchronous write average 0.96–1.58 ms (min 0.07–0.32 ms, max 1.2–6.2 ms); almost all of the cost is the read (average 1.0–1.6 ms), the write ~0.02–0.03 ms. In the old path every step did two reads and one write on the frame thread. Since the average exceeded 1 ms, the bridge caches the level: the cache is valid for 1.5 s from the moment it was read or set (a read at the start of the slide, then the cache; after a gap, a change made with keyboard keys or automatic adjustment is read again). `step` computes the target from the cache and returns immediately; the write is done on a serial queue, merged to the newest target. A failed write is logged and drops the cache. The average step from the cache is ~0.001–0.002 ms. Cost: a change made through another path within the cache lifetime is not seen during a slide; the overlay and limit logic show the targeted level, not the written one.
39. **While trrek is in front the pause state of the previous app applies.** When the settings, welcome or About window came to the front, the activation notification carried trrek's own identity and, since it was not in the list, the pause was lifted. The decision is pure inside `TrrekAppCore.FrontmostPause`: the last front app other than trrek is remembered and the pause is computed from whether that app is in the list; so removing it from the list while the window is open takes effect immediately. The menu's status line uses the same app. Cost: none.
40. **SIGTERM and SIGINT are turned into an orderly exit.** The default action of the signals is ignored (`SIG_IGN`), `DispatchSource` signal sources run `Coordinator.terminate()` on the main queue and `exit(0)`; ⌘ does not stay held. The wiring is in `TrrekAppCore.TerminationSignals` and is tested with SIGUSR2. Cost: SIGKILL still cannot be caught.
41. **The watchdog duration is read from the engine's current configuration and the clock can be injected.** `GesturePipeline` no longer takes a `lostTimeout` parameter; each time the watchdog is set it reads the duration from the engine. Since the uptime clock can be injected, tests trigger the watchdog at a known moment and verify that `tick` is called with the frame clock of the device doing the sliding. Cost: an engine lock is taken at setup (once per slide).
42. **The DMG is created with `diskutil image create from`.** `hdiutil create` gives a deprecation warning on macOS 26. The new command creates from a folder a UDZO, APFS image with the volume name "trrek" and keeps the Applications shortcut (a symbolic link); if the command is missing or fails it falls back to `hdiutil create`. Cost: the image's file system is APFS instead of HFS+ (not a problem for the macOS 26 target).

## 0.3.0 (Phase 3)

43. **The settings file is `.trrek`: JSON with its own header, local fields left out.** The file carries a `settings` object with a `format`/`formatVersion`/`appVersion` header; `launchAtLogin` and `welcomeShown` (after Task 3 also `language`; see decision 50) are not written and are kept on import (the login item and the welcome are specific to the Mac). `settings` is read with the forgiving decoder, but if `settings.schemaVersion` is newer, since the decoder would silently fall back to defaults, import counts this as `newerFormat` and rejects it. The error and confirmation state is kept in `SettingsModel` (`pendingImport`, `transferFailure`), and the alerts are attached to the root of the window, not to a tab; so the confirmation for a file coming from Finder is visible even when another tab is selected. Opening from Finder comes through `application(_:open:)`; if the file triggered the launch the URL arrives before `applicationDidFinishLaunching`, so it is queued until the coordinator starts. If several files are opened only the last one is offered (`TrrekAppCore.OpenedFileQueue`, tested). Replace applies the pending import that the alert captured with `presenting:`; it does not depend on the closing order of the binding. The pending value and the error are kept after the alert is closed, so the title does not go empty during the closing animation. While the settings window is showing an alert, a sheet (panel) or the Reset confirmation, or is reading another file, a file coming from Finder is not queued but ignored (the window comes to the front, a note is left in the log): queuing it or changing the confirmation being shown could have led to importing a file other than the one the alert named; the user can reopen the file after answering the alert. The file is read off the main actor; a file that is not a regular file or is larger than 1 MB is counted as `notSettingsFile` without being read; so is one whose `formatVersion` is less than 1. If encoding fails `encode` throws and export shows an alert instead of writing an empty file. Verification (after `make install`): `mdls` gave the type of the sample file as `com.burakseyitkara.trrek.settings` (`public.json` in the tree), `lsregister -dump` gave the type to trrek as `Owner`/`Viewer`, `NSWorkspace.urlForApplication(toOpen:)` gave `~/Applications/trrek.app`; with an invalid file `open` started the app when trrek was closed and brought it to the front when open, showing the "could not be imported" alert. Cost: no file icon, the system uses the generic document icon.
44. **All four edges offer the same action list; Swap Sides gave way to left and right edge pickers.** `Settings` now holds `leftEdge` (default Brightness) and `rightEdge` (default Volume). The old `swapSides` field is read only: if `leftEdge`/`rightEdge` are missing (or unreadable) `swapSides: true` is loaded as left=Volume, right=Brightness; it is not written on save. Since the fields were added with the forgiving decoder the schema version stays 1. When the keyboard backlight bridge is missing, Keyboard Backlight falls back to Media on every edge. Clicking the corner badge cycles through all corner actions in the order of the picker. Cost: if an older version is returned to, since `swapSides` is no longer written, the side edges go back to that version's default.
45. **The new keyboard actions send shortcuts to the front app and need no commit.** Switch Tabs ⌃⇥ / ⌃⇧⇥ (12 mm), Switch Desktops ⌃→ / ⌃← (20 mm), Zoom ⌘= / ⌘− (8 mm), Undo & Redo ⇧⌘Z / ⌘Z (10 mm); on a horizontal edge right, on a vertical edge up is the forward direction. The desktop shortcut is sent with the fn and keypad flags like a physical arrow key; the system's Control-arrow shortcut matches events carrying these flags. On the corners, Spotlight ⌘Space, Lock Screen ⌃⌘Q, Screenshot Area ⇧⌘4, Play/Pause is the play/pause media key. The keys go through the existing `KeyPoster` with the `EventStamp` stamp; like arrow keys, these shortcuts are off without the Accessibility permission. While trrek's own window is in front, Switch Tabs, Zoom and Undo & Redo steps are not sent, like scrub (⌃⇥ would move focus, ⌘Z would undo an edit); Switch Desktops is system-wide and keeps working. Cost: the key codes are ANSI positions; with a different keyboard layout ⌘= and ⌘− may fall on another character; if the user changed or turned off the system shortcuts (desktop, Spotlight, lock) the respective action does not work.
46. **Mission Control, app windows and show desktop open the system's Mission Control app with an argument.** The app is looked up by bundle identifier (`com.apple.exposelauncher`), and if not found at `/System/Applications/Mission Control.app`, and opened with `NSWorkspace` with no argument (all windows), `2` (the front app's windows) or `1` (desktop). Since a running instance would ignore the arguments, each request starts a new instance (`createsNewApplicationInstance`). The work is done on the main queue so as not to hold up the frame thread and is behind a small port (`MissionControlOpening`); tests are done with a fake port. If the app cannot be found or opened the error is written to the log, no crash. It does not depend on the user's keyboard shortcut settings. Although opening the app does not need Accessibility, the corner actions are off without permission, consistent with decision 27. Cost: the meaning of the arguments is undocumented system behavior; if it changes the action opens the wrong view or does nothing.
47. **Slide sensitivity scales only the step distances.** `slideSensitivity` (Very Low 1.6 · Low 1.25 · Standard 1.0 · High 0.8 · Very High 0.6) multiplies all step distances (`stepMM`, `appSwitchStepMM`, `scrubStepMM`, `mediaSkipStepMM` and those of the new actions) inside `ConfigMapper`; the slide start, perpendicular cancel, tap and strip width do not change. The shortest step is 0.6 × 3.75 = 2.25 mm, far above the engine's 0.001 mm tolerance; the limit haptic is in the dispatcher so it is not affected. Cost: at High the level step is equal to the slide start threshold (3 mm), at Very High (2.25 mm) it is shorter than it; in both, the frame that starts the slide also produces the first step (pinned by an engine test), i.e. a short 3 mm slide changes the level by one notch.
48. **Corners are corners even when their adjacent edges are Off.** `Geometry.zone(of:)` determines the strips with geometry only; an edge being `.off` closes only the plain region of that edge. Previously an Off edge also silently closed the corners next to it (on the top/bottom edge too; it became prominent in Phase 3 when the side edges became selectable as Off); the Corners tab, on the other hand, showed the corner action as active. Now the double tap of a corner works independently of its edges; a slide starting from a corner toward an Off edge goes to `spent` through the `action != .off` check in `handleCandidate` and produces no command, a slide toward the other edge works as before. Cost: when a corner action is Off, touches in that corner no longer count as the plain region of the adjacent edge; for example with the left edge Off and the top left corner Off, a double tap at the point (5, 75) does not do play/pause on a Media top edge (the corner strip is as wide as the edge width).
49. **Localization with `.lproj/Localizable.strings`, the key is the English source text.** The files are under `Sources/Trrek/Resources/{en,tr}.lproj/`; the SwiftPM target leaves the folder out with `exclude`, `build-app.sh` puts it into the bundle's `Contents/Resources` folder with the existing copy step, so `Bundle.main` finds it and `swift build`/`swift test` do not produce a resource bundle. SwiftUI literal texts (`Text("…")`, `Button("…")`, `Picker("…")`, `.alert("…")`, `.help("…")` …) are translated automatically as `LocalizedStringKey`; every text passed as a `String` (menu items, window and panel titles, alert titles, `TrrekAppCore` labels) is translated with `String(localized:bundle: .main)`. Library code also passes `bundle: .main`; in tests the main bundle is the test runner, no translation is found and the English key is returned, so tests expecting English pass unchanged. The overlay's "No DDC" label is produced as a fixed literal on the frame thread and looked up as a key when shown on the main thread (no per-frame allocation is added); the scrub label ("+15 s") is also produced in English on the frame thread, and when shown its unit is translated with the `"%@ s"` format (Turkish "+15 sn"). In formatted texts Swift interpolation produces the key (`"Paused in %@"`, `"%lld%%"` for percentage); composite expressions such as edge card titles are full-sentence keys per edge so that the translation can set the word order freely. `LocalizationTests` checks that the key sets in the two languages are the same, the English values are the same as the key, the Turkish format specifiers are the same as the key (including positional specifiers) and there are no duplicate keys; with a source scan, that every key used is in the `en` file and every key in the `en` file is used. The scan reads the literal texts in the known call forms, matches interpolation with any specifier; it also counts literal texts of two or more words that fall outside these calls (excluding log lines, comments and shell scripts, with a two-word allow list) as untranslated interface text and fails. Cost: the scan is a regular expression, not a parser; it cannot see a single-word text built elsewhere and passed as a `String`, nor dynamic keys (listed by hand); `InfoPlist.strings` translates only the name of the `.trrek` type, the copyright line stays in English.
50. **The language choice writes the app's `AppleLanguages` preference; a relaunch is required.** When `Settings.language` (`system`, `english`, `turkish`; read with the forgiving decoder; since the interface language belongs to this Mac's user it is not written to the `.trrek` file, like Launch at Login, and import and Reset to Defaults keep it) changes, `Coordinator.apply` writes `["en"]` or `["tr"]` to trrek's own defaults domain, and deletes the key for `system`; what to do is computed by the pure function `TrrekAppCore.LanguagePreference.change(from:to:)` and reading looks only at trrek's persistent domain (the global domain and the command line `-AppleLanguages` do not count). Since Foundation chooses the language once at launch, the language does not change in the running process: the localization shown at launch (`Bundle.main.preferredLocalizations.first`) is kept, the chosen language is resolved to a localization with `LanguagePreference.localization(for:available:systemLanguages:)` (the `AppleLanguages` in the global domain for `system`) and when the two differ the "Relaunch trrek to use the new language." row appears in the General tab with a Relaunch button; so when the system is Turkish, switching from System to Turkish does not ask for a relaunch. Relaunch starts a short wait script with `/bin/sh` (the PID and bundle path are passed as positional parameters, not embedded in the script), then exits in an orderly way with `NSApp.terminate`; the script waits at 0.1 s intervals until the process ends (at most 10 s) and opens the same bundle with `/usr/bin/open`. Since a bundle opened while trrek is running only brings the running instance to the front and opens its settings, no new instance is opened before the old one closes; two instances do not run at the same time with `open -n`. If the setting and the preference mismatch at launch (defaults were changed by hand or the app stopped between two writes) the preference is written according to the setting and takes effect at the next launch; the setting is the source because it is what is saved and kept on reset. The button is not shown in a development build running outside a bundle. Since the language chosen for trrek in System Settings › General › Language & Region › Applications is written to the same key, if at launch the preference shows a supported language that differs from the setting, the setting adopts that language and is saved (`LanguagePreference.adoptedLanguage(fromStored:setting:)`; comparison is by language code, "tr-TR" = "tr", an equivalent value is not rewritten); if there is no preference or it shows an unsupported language the setting is the source and the preference is written accordingly. Cost: a language change needs a relaunch; the wait script is a separate process that lives until trrek closes.
51. **Turkish text rules.** The names in Apple's Turkish macOS interface are used: Ayarlar, Genel, Kenarlar, Köşe ve Dokunma, Gelişmiş, Ses, Parlaklık, Klavye Aydınlatması, Erişilebilirlik, İzleme Dörtgeni, Sistem Ayarları, Vazgeç, Tamam. Menu items and titles are written with every word capitalized, descriptions in sentence case. So that app names do not take suffixes, the pattern "%@ İçin Duraklat" / "%@ İçin Sürdür" / "%@ için duraklatıldı" is used (since the vowel harmony of the suffix changes with the app name a name + suffix form cannot be built). Tab names must fit in the settings window's tab bar: the bar's segments are as wide as the longest name and a bar that does not fit falls into the overflow menu; so "Corners & Taps" becomes "Köşe ve Dokunma" and `SettingsTabBarLayoutTests` limits each name to 112 pt. `trrek` stays lowercase, suffixes are added with an apostrophe (trrek’ten, trrek’i, trrek’e). Key names are as in System Settings › Keyboard: Control becomes "Kontrol", Command becomes "Komut", Shift and Option are not translated; Mission Control and Spotlight are not translated; key symbols are kept; seconds "sn" ("+15 sn"), percentage is written "%50" in the Turkish layout. The Trackpad hint uses the system's labels in quotes exactly ("Araştırma ve veri algılayıcıları", "Tek Parmakla Kuvvetli Tıklayın"); Launch at Login becomes "Oturum Açıldığında Başlat", following the system term "Oturum Açıldığında Aç", Screenshot becomes "Ekran Resmi", haptic becomes "Dokunuş Geri Bildirimi". In the picker the languages appear under their own names (English, Türkçe), "System" is translated. Cost: if system terms change the translation is updated by hand.

## 0.4.0 (update check)

52. **Updates are read from a separate public repository and only announced and downloaded.** *(The flow changed with decision 71.)* Since the source repository is private, the app reads, without authentication, the `releases/latest` endpoint of the public `burakseyitkara1/trrek-releases` repository, which carries only the release files (the limit of 60 requests per hour per IP is more than enough for one check a day). The tag's `vX.Y.Z` version, `html_url`, `body` and the `browser_download_url` of the asset whose full name is `trrek-vX.Y.Z.dmg` are used; drafts and prereleases and non-https links are rejected. The app does not replace itself: it downloads and opens the disk image, the user does the install (for in-place install see decision 65). Cost: the install is manual drag and drop; if the format of the GitHub API changes the check says "Couldn’t check for updates".
53. **Privacy: the request carries only the version.** Each request is made in its own ephemeral `URLSession` (no cookie, cache or credential store; the session is invalidated after the job) and sends only `Accept: application/vnd.github+json` and `User-Agent: trrek/<TrrekVersion.string>`; `--assume-version` does not change the User-Agent. The server naturally sees the IP address; the README says so. While "Check for Updates Automatically" is off no automatic request is made. Cost: none.
54. **No timer; the check is made at opportune moments and when the policy allows.** 10 s after launch and wake as a one-shot (`DispatchWorkItem`, a new one replaces the pending one; so the network can come up), when the menu opens and manually. Pure `UpdateCheckPolicy`: manual always; automatic only when the setting is on, the last successful check is older than 24 hours and — in addition to the brief — the last failed check is older than 1 hour (so as not to send a request on every menu open while offline); a future date (clock set back) counts as old. While a check is in progress automatic triggers are skipped. Measurement: when the check was made 10 s after launch, `make perf` showed 0.4–0.5% CPU at the 30th second (including launch, the damped average of `ps`) and a 13.8 MB footprint; on a launch without a check 0.0% and 13.2 MB. Cost: about 0.6 MB of resident memory once a day (network frameworks are loaded); a Mac that does not sleep for a long time and whose menu is not opened does not check until the next opportunity even if it passes 24 hours.
55. **The notification once per version, the permission requested when first needed.** *(Removed with decision 71.)* `UNUserNotificationCenter` is used only inside trrek's bundle (the `Bundle.main.bundleIdentifier` check; in tests and `swift run` the center is never called since it throws an exception in a process without a bundle). The delegate is assigned in the first line of `applicationDidFinishLaunching` so that a notification click that launches trrek is also delivered; the delegate stores a click that arrives before the handler is wired. When the automatic check first finds a new version the permission is requested (`.alert`), and if granted "trrek X.Y.Z is available / Click to download." is sent; without permission only the menu item remains. `notifiedVersion` is written on every new version found (in a manual check too; the user saw the alert). The banner is shown while trrek is in front too. No extra key is needed in Info.plist for an `LSUIElement` app; the notification icon comes from `CFBundleIconFile`. Cost: the permission request appears when the first new version is found, while the user is doing something else.
56. **The download goes to `~/Downloads/trrek-vX.Y.Z.dmg`, with the quarantine attribute.** *(Removed with decision 71.)* A file with the same name is deleted first; the file is quarantined like a browser download (`quarantineProperties`) so that Gatekeeper checks the app inside on first launch; then `NSWorkspace.open`. Timeouts are 60 s idle, 10 min total: in a live trial on a ~30 KB/s connection the 15 s idle time chosen for the feed was exceeded and the download stopped halfway. The error alert opens the release page with "Open Download Page". Cost: download progress is not shown (0.6 MB); if the quarantine cannot be written it is only noted in the log.
57. **The update state is kept separate from the settings.** *(Changed with decision 71: `notifiedVersion` was removed; a recorded update shows the menu row and the icon badge.)* `lastUpdateCheck`, `lastFailedUpdateCheck`, `notifiedVersion` and `availableUpdate` (version, DMG and page address, notes; JSON) are in separate keys in the app's defaults domain and do not enter the `.trrek` file. `checkForUpdatesAutomatically` (default on, forgiving decoder) is a setting: it is exported and Reset to Defaults turns it on. A recorded update that is not newer than the running version is deleted at launch, so the menu item disappears after an update. Cost: none.
58. **`--assume-version X.Y.Z` changes only the version the checker compares.** It is for trying the flow by hand against the real feed; `TrrekVersion.string`, About and the User-Agent do not change. An invalid value is ignored. The state is written to a separate defaults domain (`com.burakseyitkara.trrek.assumed-version`), the real schedule and per-version notification are not affected (after review; see decision 64). Cost: none.
59. **`release.sh` also publishes the release to the public repository.** After the release in the private repository, the same DMG and zip are published with `gh release create vX.Y.Z --repo burakseyitkara1/trrek-releases --title "trrek X.Y.Z" --notes-file <section>`; the notes are the `## [X.Y.Z]` section extracted by the `changelog_section` function (it was tried that for v0.3.0 the output is identical to the live release body). If the section is missing or empty, the public repository is not reachable or the tag already exists there, the script fails before the build and notarization. `--no-publish` publishes to neither. If the public release fails the private release remains and the script prints the command to run by hand. Cost: publishing to two repositories is sequential, not atomic.
60. **The General tab scrolls; the Coordinator was split.** With the new Updates section the tab's content grows to ~615 pt and is shown in the 640×480 window with the existing grouped `Form`'s own scrolling (the tab was already at the limit). The update wiring moved to `Coordinator+Updates.swift`, `grantAccessibility` to `Coordinator+Events.swift`; the type body of `Coordinator` stays at the lint limit. Manual check alerts are shown as a sheet on the settings window when requested from it and as an app-modal `NSAlert` when requested from the menu. Cost: the lower part of the General tab (Export/Import, Reset) is not visible without scrolling.
61. **The download and page addresses are pinned to the release repository; the recorded value is also verified.** Review finding: the feed or defaults (anything running as the user can write them) could have had a DMG downloaded and opened from an arbitrary https server; another developer's notarized DMG passes Gatekeeper. `ReleaseInfo.hasExpectedLinks`: the DMG address is exactly `https://github.com/burakseyitkara1/trrek-releases/releases/download/v<X.Y.Z>/trrek-v<X.Y.Z>.dmg` (version the same as the tag; no query, user or port), the page is under `https://github.com/burakseyitkara1/trrek-releases/releases` (no user, port, query, fragment or `..`). A version that does not match when the feed is read is an `unexpectedLink` error ("The update information points to an unexpected address."); `UpdateStateStore.availableUpdate` ignores a record that does not match. The first address is fixed, the server's redirect to the download host is followed. Verifying the Team ID of the DMG signature before opening it was left outside the brief. Cost: if the repository moves or GitHub changes the download address format, the check does not accept the new version and the app must be updated.
62. **Usage description for the Downloads folder.** *(Removed with decision 71.)* On the first write of a non-sandboxed app to `~/Downloads` the system asks for permission once; `NSDownloadsFolderUsageDescription` ("trrek saves update disk images to your Downloads folder.") was added to `Info.plist`, its Turkish version is in `tr.lproj/InfoPlist.strings`. Since the system looks up usage descriptions by the Info.plist key, the key of these lines is the key name, not the value; `LocalizationTests` checks that the English value is the same as the one in Info.plist. Without permission the move fails with a permission error, the temporary file is deleted and the "Couldn’t download…" alert offers "Open Download Page" (tested: a non-writable folder). Cost: a system prompt on the first download.
63. **A DMG whose quarantine cannot be written is not opened, only shown in Finder.** *(Removed with decision 71.)* Otherwise the app inside could be copied without Gatekeeper's first-launch check. `UpdateDownloader` returns `DownloadedDiskImage(file:isQuarantined:)`. Cost: in that (unexpected) case the user opens the DMG themselves.
64. **Small fixes after review.** Refreshes that arrive while the menu is open (the check started by the menu opening) are applied when the menu closes, in the next main queue turn; so the "Update Available" item does not shift the items under the cursor and the action of the selected item is sent before the setup. While a check or download is in progress "Check for Updates…" and Check Now are disabled and a manual check does nothing (no second alert or silent Download). Clicking the notification when no known update remains does a manual check. A manual check takes the settings window with a closure that holds it weakly, so a window closed while downloading is released (alerts then appear app-modal). `--assume-version` uses a separate defaults domain. `\r\n` line endings in release notes also count as lines. `release.sh` writes the notes to `dist/release/trrek-vX.Y.Z-notes.md` (the retry command points to this file; the temporary folder is deleted on exit) and drops the `[X.Y.Z]: https://…` link definitions from the section. Turkish "trrek %@ en son sürüm." Cost: the result of a check that started while the menu was open appears the next time the menu is opened.

## 0.4.0 (in-place install)

65. **A downloaded update is installed in place; the disk image is only the fallback path.** *(The flow changed with decision 71.)* After the download `UpdateInstaller` (`TrrekAppCore`) first checks the location (decision 68), then mounts the DMG with `diskutil image attach --plist --readOnly --nobrowse --mountPoint <temporary folder>`; since `hdiutil attach` gives a deprecation warning on macOS 26, `hdiutil attach -plist -readonly -nobrowse -noautoopen -mountpoint` is tried only if `diskutil` fails. The mount point is `$TMPDIR/trrek-update-<UUID>`, it is not visible in Finder and no window is opened. `trrek.app` (it must be a folder, not a link) is copied with `ditto` into a fresh staging folder given by `FileManager.url(for: .itemReplacementDirectory, appropriateFor: <bundle>)`; this folder is on the same volume as the bundle, so the replacement is a rename, not a copy. The image is ejected on every path with `diskutil eject <whole disk>` (with `hdiutil detach -force` if that fails), the mount folder is deleted only if empty (`rmdir`); the staging folder is deleted on a verification error, on Later, after the install and on an install error. For the verified app, a "trrek X.Y.Z is ready to install" alert offers Install and Relaunch / Later. Install removes the quarantine (decision 67) and replaces the bundle with `FileManager.replaceItemAt(_:withItemAt:backupItemName: ".trrek-previous", options: .usingNewMetadataOnly)`: the backup stays hidden and without an `.app` extension next to the bundle until the swap succeeds, then is deleted; on error the old bundle stays in place. Then the relaunch script from decision 50 opens the same path and trrek exits in an orderly way with `NSApp.terminate` (held keys are released, the cursor comes back); if the script cannot be started the "trrek X.Y.Z is installed / Quit trrek and open it again…" alert appears. Later keeps the DMG and the menu shows "Install trrek X.Y.Z…"; this item, and clicking the notification, remount the image and verify again, and download again if the DMG was deleted. The Later state is only in memory: a restarted trrek shows "Update Available…" and downloads again (instead of trusting the old DMG). File and process work is done off the main actor, on a global `DispatchQueue`; each command is terminated after 120 s with a one-shot `DispatchWorkItem` (no repeating timer). The steps are behind small protocols (`DiskImageAppExtracting`, `UpdateVerifying`, `BundleReplacing`, `InstallLocationInspecting`; `UpdateInstalling` and the relaunch closure for the controller); success, every error and cleanup on every path are tested with fake steps. The `--assume-version` flow also continues, so a released version can be installed over a copy. The real image, signature and Gatekeeper steps were tried with `UpdateInstallReleaseTests`, which runs when `TRREK_UPDATE_DMG` is given (v0.3.0 DMG: all 16 files copied were quarantined, none after the install; no image remained in `hdiutil info`). Cost: during the install progress is visible only in the menu; the Later state is lost on restart.
66. **Verification: Developer ID signature, Gatekeeper and `Info.plist`.** The prepared app is checked with `SecStaticCodeCheckValidity` with the flags `kSecCSCheckAllArchitectures | kSecCSStrictValidate | kSecCSCheckNestedCode`, against the requirement `anchor apple generic and identifier "com.burakseyitkara.trrek" and certificate 1[field.1.2.840.113635.100.6.2.6] exists and certificate leaf[field.1.2.840.113635.100.6.1.13] exists and certificate leaf[subject.OU] = "R2333A9MFR"`. The Developer ID intermediate certificate and application certificate fields were added to the requirement in the brief; so the requirement is the same as the releases' designated requirement (`codesign -d -r-`) and the same team's Apple Development certificate does not pass. After the signature (the signature seals `Info.plist`) `CFBundleIdentifier` must be `com.burakseyitkara.trrek`, `CFBundleShortVersionString` exactly the `X.Y.Z` text of the version found (no prefix or suffix accepted) and newer than the version the checker compares (real or `--assume-version`) (`UpdateInstallPolicy.identityProblem`, pure and tested). Finally `/usr/sbin/spctl --assess --type execute` must exit with 0; since the `SecAssessment` API is not in the public SDK headers the command is used. Measurement (v0.3.0 DMG): the release passes; a copy re-signed with `codesign --force --sign -` was rejected with -67050 (requirement not satisfied), a copy with a modified `Info.plist` version with -67030 (invalid Info.plist) at the signature check, and `dist/trrek.app`, signed locally with Developer ID but not notarized, only at the Gatekeeper check (`spctl` exit code 3). An update that fails verification is not installed and the disk image is not opened: "trrek X.Y.Z couldn’t be verified" states the reason, the DMG stays in Downloads, Open Download Page opens the release page. Cost: `spctl` alone depends on the user's Gatekeeper setting (accepts everything when it is off); so after review the `notarized` requirement was also added (decision 69).
67. **The quarantine of the installed copy is removed.** Every file copied from a quarantined DMG carries `com.apple.quarantine`; the first launch of such an app asks for Gatekeeper approval and would hold the relaunch behind a system window. Since trrek itself checks the signature and notarization, just before the replacement the attribute is removed from every file in the prepared copy without following links (`removexattr(…, XATTR_NOFOLLOW)`). The quarantine on the DMG itself is kept (decisions 56, 63), so an app installed by hand in the fallback still goes through Gatekeeper. Cost: the system's first-launch approval is not shown for the installed app; the assurance is the checks in decision 66.
68. **Fallback rules and the Accessibility permission.** *(The flow changed with decision 71.)* In these cases trrek does not replace itself and, after the "trrek X.Y.Z couldn’t be installed automatically" alert, opens the disk image as before (only shows it in Finder if the quarantine could not be written, decision 63): the bundle is not a real `.app` (`swift run`, tests), the path contains `/AppTranslocation/`, the bundle is on a disk image (the DiskArbitration device model "Disk Image") or a read-only volume, the bundle or its folder is not writable, the image cannot be mounted or the app cannot be copied, the replacement fails. The location is checked again before the preparation and right before the replacement (the app may have been moved while the user was at the alert); the decision is pure in `UpdateInstallPolicy.issue(for:)` and tested. The Accessibility permission is held in TCC with the bundle identity and designated requirement; since every release is signed with the same Developer ID, the new version's designated requirement is the same and the permission is preserved (the signing identity note in the README). Cost: in an `/Applications` install that a non-administrator user cannot write, the update is again dragged by hand.
69. **After review: re-verification right before and after the install, DMG signature, `notarized` requirement.** The prepared app waits, until the user answers the alert (minutes, hours), in the `TemporaryItems/NSIRD_…` folder that any of the user's processes can write; if a process running as the same user changed it, it would have been moved into trrek's place with its quarantine removed and opened. Now `install` checks the location, removes the quarantine (this does not affect the signature seal), reruns the full verification (signature + requirement, `Info.plist`, notarization), replaces the bundle with `replaceItemAt(… .withoutDeletingBackupItem)` and verifies the app in place once more; if this last check fails the backup is put back (`restore`), and the backup is deleted only after success. A verification error is a "couldn’t be verified" alert, the DMG is not opened. The disk image itself, before it is mounted (before the kernel parses the file system), is checked with `SecStaticCodeCheckValidity` against the release team's Developer ID signature (`anchor apple generic`, Developer ID fields, `leaf[subject.OU] = "R2333A9MFR"`; the identifier is not pinned since it derives from the DMG name); `release.sh` already signs and staples the DMG. An unsigned DMG or one from another team is a signature error (not a fallback). Notarization is now checked first with the `notarized` requirement (stapled ticket, offline), `spctl --assess` stays as a second opinion; so a non-notarized app is rejected even when Gatekeeper is off. Measurement (v0.3.0 DMG, `UpdateInstallReleaseTests`): the release DMG and the app inside pass; a copy re-signed ad hoc after being prepared was rejected right before the install and the installed copy did not change; an unsigned DMG created with `diskutil image create from` was rejected without being mounted (-67062); the non-notarized `dist/trrek.app` was rejected at the `notarized` requirement (-67050). Cost: during the install the verification runs three times (one `spctl` each, ~1 s in total).
70. **After review: cleanup of interrupted installs and stability.** At launch (once, off the main actor) and before every preparation the `$TMPDIR/trrek-update-*` folders are scanned: mounted ones (the folder is on a different device from its parent folder) are ejected, empty ones are deleted with `rmdir`; no process is started, if there is nothing left only a directory is listed. If the mount command was stopped by the timeout and the image stays mounted without its device being known, the mount point is also ejected the same way. Before the preparation, old staging folders next to the new staging folder that contain only a `trrek.app` are deleted. At launch and before every replacement the old `.trrek-previous` backup next to the bundle is deleted (`replaceItemAt` could delete one with the same name but still leave the new one). If trrek quits while the "Ready to install" alert is open, `Coordinator.terminate` deletes the prepared app. If the replacement fails and the bundle is not in place, the previous app is moved back from the error's `NSFileOriginalItemLocationKey` value or from the backup; the protocol documentation promises only this. The standard output of commands is written to a temporary file instead of a pipe (a helper process that inherits the output cannot hold the call up) and on timeout SIGKILL is sent 5 s after SIGTERM (two one-shot work items; disabled when the command finishes). If the relaunch fails the installed version is remembered: the menu shows no update item, no download is made, a manual check and the notification repeat the "is installed / Quit trrek and open it again…" alert. The menu names the stage: "Verifying trrek X.Y.Z…", "trrek X.Y.Z Is Ready to Install", "Installing trrek X.Y.Z…". The location check and the creation and deletion of the staging folder are also inside `runOffMain`. Cost: if two copies of trrek are running at the same time, the launch scan of one may eject the other's currently mounted image (not a supported use).

## 0.4.0 (update in the menu bar)

71. **The update is in the menu bar from start to finish: badge, menu row, live progress, install without confirmation.** After trying the first flow (notification, download to Downloads, "ready to install" alert, Later) the user wanted a simpler flow; this decision removes 55, 56, 62 and 63, and changes the flow in 52, 65 and 68. While there is a known update a filled up arrow is drawn in the top left corner of the menu bar icon (Accessibility at the top right, the hold key dot at the bottom right; the arrow is cut out in the template image with a 1 pt transparent ring); the icon and the VoiceOver description are built with `MenuIcon.State` ("trrek (update available, …)"). The "Update Available: trrek X.Y.Z" row at the top of the menu is `UpdateRowView` as `NSMenuItem.view`: it handles the click itself in `mouseUp`, so the menu stays open and the row becomes "Downloading trrek X.Y.Z…" in place (a determinate progress bar, received/expected bytes), "Installing trrek X.Y.Z…" (an indeterminate bar); then trrek installs directly and relaunches. The row has the same height in every state (the bar to the right of the title), and its width is computed up front for the longest title of every state, so the layout of the open menu does not change. Since an item with a view does not draw its own highlight, while `enclosingMenuItem.isHighlighted` the row draws the selected menu item color; the arrow keys reach the row and Return sends the item's action (the same start), the accessibility role is menu item, its value is the percentage. The states are in the pure state machine `TrrekAppCore.UpdateRowState` (`available → downloading(progress) → installing`, `failed`, `browser`, `relaunch`; progress redraws only when the whole percentage changes) and are tested. The download is done with `URLSessionDownloadDelegate`; progress comes from the background queue to the main actor with `DispatchQueue.main.async`. Verification: in a process where `NSApplication` was set up, main queue blocks, `@MainActor` tasks and common-mode blocks ran inside `RunLoop.main.run(mode: .eventTracking)` (a block added only to the default mode did not run); so progress and state changes reach the row even while the menu is being tracked. If only the presence of the row changes while the menu is open (a new check result) it is rebuilt when the menu closes (decision 64). There is no confirmation step: download → mount → copy → verify → re-verify right before replacement → replace → verify the installed app (decisions 65, 66, 69 unchanged) → relaunch. The DMG is downloaded to `~/Library/Caches/com.burakseyitkara.trrek/Updates/trrek-vX.Y.Z.dmg` (the quarantine attribute is kept) and deleted after the install or an error and at launch; `NSDownloadsFolderUsageDescription` was removed, the Downloads permission is not requested. The notification was removed completely (`UserNotifications`, the permission request, the delegate, `notifiedVersion`); the automatic check only shows the badge and the row. A download or verification error makes the row "Update Failed — Try Again" (the reason is written to the log), clicking starts over; when trrek cannot replace itself (the location cases in decision 68, a mount/copy or replacement error) the release page opens in the browser and the row becomes "Update in Browser…", clicking reopens the page; the DMG is not opened. If the relaunch cannot be started the row becomes "Relaunch to Finish Updating". There is no modal alert in this flow. A manual check shows a short alert only when up to date or on failure; if a new version is found the badge and row appear instead of an alert, and in General under Check Now the same state is shown with a row and a button (Update Now, Try Again, Update in Browser…, Relaunch; progress while downloading). The install error messages (location, verification) were removed together with their translations since they are not shown in the interface; the error kinds stay in the log. Cost: download and install start when the row is clicked, without user confirmation (the click is the confirmation); the running app's settings window or open work closes without warning; the highlight color of `UpdateRowView` is an approximation of the system menu highlight.
72. **After review: checks and clicks while an update is in progress.** Clicking the row (or Update Now) while a check is in progress is no longer swallowed: the update starts with the known version without waiting for the result of the check (`startUpdate` rejects only an update in progress, not a check). The update is bound to the version it started with: the flow is kept as `(release, state)`, each step and progress changes only that version; the row of an update in progress (and one waiting for a relaunch) stays in place even if a check that ends in the meantime says "up to date" or finds a newer version; a second concurrent flow does not start. While an update is in progress automatic checks send no request at all. The location (translocated, read-only, non-writable, disk image) is also asked before the download (`UpdateInstalling.locationIssue()`), so the user is directed straight to the release page without watching the progress bar; `prepare` asks again. In the menu "Check for Updates…" is disabled in place in the open menu while a check or update is in progress, and "Quit trrek" while trrek is replacing itself (`installing`) (`UpdateMenuItems`); so the final verification and relaunch are not interrupted. While the row is busy it is disabled in accessibility, the press action returns `false`, the menu item's title follows the state. Progress is reported in `DownloadDelegate` when the whole percentage changes, at most ~101 blocks go to the main queue. `UpdateInstalling.discard` (a leftover of the confirmation step) was removed. Cost: an update that starts while a check is in progress installs the known version, not the newer one the check might find; the newer one appears at the next check; quitting with SIGTERM is still possible during the install.
73. **Merging with local verification when the CI quota is exhausted.** On 2026-11-06 GitHub Actions jobs could not be started because of the spending limit. By the user's decision, until the quota renews, PRs are merged when `make check` (build, test, format, lint) passes locally on the PR's last commit, and a local verification comment is written on the PR; the independent review rule applies as is. Cost: an error specific to the CI environment (Xcode 26.6, Intel runner) may show up after the merge; when the quota renews CI is run once by hand on main.

## Security audit (2026-11-08)

74. **The distributed binary is stripped; the symbols stay locally as a dSYM.** The audit (M1) found that the app's binary carried the source and object paths of the build folder (the home folder with the user name) and ~37,500 symbols. `scripts/build-app.sh` now produces `dist/trrek.app.dSYM` with `dsymutil` before the binary is copied, then cleans the binary with a plain `strip` (only the symbols required by the dynamic linker remain; the default "all symbols" strip for application targets) before signing. The Swift runtime metadata is in sections, not in the symbol table; the app opens and closes with `--quit-after`, and runs after `make install`. The script fails if an `SO`/`SOL`/`OSO` entry or the path of the working folder or `$HOME` remains in the binary. `release.sh` keeps the dSYM as `dist/release/trrek-vX.Y.Z.dSYM`; it is not published, crash reports are symbolicated from this file by UUID. `-debug-prefix-map` was not needed: no path remains in the binary after the strip. Measurement: the signed binary 2,671,776 → 1,150,656 bytes, symbols 37,537 → 1,112 (1 defined). Cost: the crash report of a build whose dSYM is lost stays unsymbolicated.
75. **A release requires a successful `ci` run for the commit being published.** The audit (M2) found that 0.4.0 was published without CI running at all (decision 73). In release mode `release.sh` looks for a successful run for the full SHA of HEAD with `gh run list --commit <HEAD> --workflow ci --status success` and stops if there is none. Since PR runs test the branch, not the squash commit, before a release `gh workflow run ci --ref main` is run on `main` and waited for (the README and the script header say so). `--allow-missing-ci` skips the check and prints a conspicuous warning; it is used only when GitHub Actions cannot run at all (decision 73), and when it works `ci` is run by hand for that commit. Cost: a `main` run before every release (macOS minutes).
76. **Workflow actions are pinned to a full commit SHA.** The audit (L1): `actions/checkout`, `actions/cache`, `actions/upload-artifact` were on a major version tag. Now they are in the form `@<40-digit SHA> # vX.Y.Z` (the commit the tag points to was found with `gh api repos/actions/<name>/git/ref/tags/<tag>`, all were lightweight tags); the `github-actions` ecosystem in `.github/dependabot.yml` updates the SHA and the version comment together. The "require SHA pinning" option in the repository settings was not changed in this PR; the user turns it on at publication. Cost: version upgrades come only through Dependabot PRs.
77. **The feed response is limited to 1 MB, the download to 64 MB.** The audit (L2). `ReleaseFeedClient` reads the response as a stream with `URLSession.bytes(for:)`; if `expectedContentLength` exceeds the limit it throws `ReleaseFeedError.tooLarge` without reading anything, and as soon as the bytes read exceed the limit, and the session cuts the transfer with `invalidateAndCancel`. The delegate of `SessionFileDownloader` cancels the task when the expected or written bytes exceed 64 MB; `tooLarge` is returned instead of a cancel error, no file is left (even if the transfer finished before the cancel). The limits can be reduced in tests (`maximumSize`); they are tested with fake byte arrays and a fake protocol (with and without `Content-Length`). The new error text visible in a manual check is "The update information is larger than expected." (in its Turkish version). Cost: if a release DMG larger than 64 MB is published it cannot be downloaded without raising the limit (today ~1 MB).
78. **A version older than the running version is never installed under any condition.** The audit (L3): since `--assume-version` lowers the version being compared, someone controlling the feed could have had an old but signed and notarized version installed. `UpdateInstaller` takes the compiled `TrrekVersion` (`runningVersion`, can be given in tests) as the base: `UpdateInstallPolicy.downgradeProblem` returns `UpdateVerificationFailure.olderThanRunning` if the version is smaller; `prepare` checks before mounting, `install` checks again before replacing. An equal version is allowed, so a manual install trial with `--assume-version` on a copy keeps working. The error is a verification error: the browser does not open, the row becomes "Update Failed — Try Again". The checker did not change (the badge is still shown). Cost: the check is made after the download (in that case the DMG is downloaded for nothing and deleted).
79. **Error descriptions and device identifiers are written to the log privately.** The audit (L4). `Error.domainAndCode` and `Logger.error(_:_:)`/`fault(_:_:)` were added to `TrrekPlatform`: the fixed text and the error's domain and code are `.public`, the `String(describing:)` description is `.private`. ## 0.5.0 (edges per app)

86. **Edges per app follow the front app, and never interrupt a gesture.** An app can have its own action for each edge (`AppEdgeProfile`, `nil` = Same as All Apps); the profile is resolved in `ConfigMapper` before the keyboard backlight fallback and the Accessibility gating, so both keep applying to the action the edge actually runs. The app is the one the pause logic uses (`FrontmostPause.bundleID`), so a trrek window in front keeps the previous app's edges, and a paused app stays paused whatever its profile says. Changing the configuration with `update(config:)` commits an active slide, which would cut a Switch Desktops slide short when the desktop change brings another app to the front. So the engine got `updateWhenIdle(config:)`: the decision is the pure `DeferredConfig` (a configuration equal to the current one changes nothing; while a finger is a candidate or a slide is `sliding`/`lost` it waits, a later request replaces it; otherwise it applies at once). The engine settles the waiting configuration itself, under its own lock, at the end of every locked body that can end a gesture (frame, watchdog tick, pause, hold key, reset) and before a new gesture starts in `idle`; this needs no signal to the main actor, no polling and no timer, and it cannot miss the moment the engine goes idle. When nothing waits it costs one optional check per frame, with no allocation. A settings change still goes through `update(config:)` as before. Limits: at most 50 profiles (a longer stored or imported list keeps its first 50), trrek itself is never one, duplicates keep the first. The Edges tab gets an Edges For picker at the top instead of a new tab (the Turkish tab bar has no room, `SettingsTabBarLayoutTests`); Add App… reuses the Paused Apps app chooser, now `AppChooser`. The selected scope is window state in `SettingsModel` (no `@State`) and goes back to All Apps when its app disappears (import, reset). A configuration that follows the front app keeps a pending first tap of a double tap when its corner keeps its action or its edge stays media (`GestureEngine.tapSurvives`): with tap to click, the first tap often brings another app to the front, and dropping the tap swallowed the double tap (review). A settings change through `update(config:)` still drops it. The menu shows "Edges set for <App>" only while trrek is active (trusted, trackpad found; otherwise the status line explains why nothing runs), the app is not paused and its edges differ from the All Apps ones (`edgeActions(for:)` compared, so a profile that repeats the All Apps actions shows nothing). In the Edges tab the "These edges apply while <App> is in front." note is the Edges For picker's caption and "Remove <App>" has its own row, so a long app name does not crowd one row in Turkish. Cost: an app's edges apply only after the gesture in progress ends, so a finger resting on an edge as a candidate across an app switch slides with the previous app's action; the Edges tab is one row taller and scrolls further.

## 0.5.1 (update retries)

87. **Transient update failures are retried; a final failure says why.** On 2026-11-09 GitHub answered release downloads with 504 Gateway Timeout during an incident, and the update failed at once with only "The update failed.". `RetryPolicy` (TrrekAppCore) now wraps both the feed request (`ReleaseFeedClient.latestRelease`, a new session per try) and the disk image download (`UpdateDownloader`, which restarts the download from the start and tells the row's progress the size is unknown again). Retried: HTTP 5xx and 429, and the URL errors `timedOut`, `networkConnectionLost`, `cannotConnectToHost`, plus `notConnectedToInternet`, `cannotFindHost` and `dnsLookupFailed`, since Wi-Fi often joins a few seconds after wake (when the automatic check runs). Not retried: `dataNotAllowed` and `internationalRoamingOff` (cellular data turned off does not recover by itself), cancellation, other 4xx answers, other URL errors (including TLS failures), and everything refused on content (too large, malformed, unexpected links) or verification. At most two retries follow the first try, after 2 s and 5 s; each wait is a one-shot `Task.sleep` through an injectable `RetrySleeper`, so tests run instantly and no timer exists. A 429 or 503 answer's `Retry-After` (seconds or an HTTP date, carried in `ReleaseFeedError.httpStatus(_, retryAfter:)`) is waited instead when it is at most 30 s; a longer one ends the attempts, since waiting minutes inside a click would look like a hang. The size limits (decision 76's 1 MB and 64 MB) apply to every try; a failed try keeps no file. The row keeps showing Downloading during a retry: its progress is reset to indeterminate as soon as a retry is decided (before the wait), and only a 200 answer's bytes count as progress, so an error page (the incident's 504) never fills the bar. A download that ran out of the whole-transfer limit (`SessionFileDownloader.resourceTimeout`, 600 s) fails as `DownloadTimeLimitReached` and is not retried, since a restart from zero on the same slow connection would very likely run out of time again; an idle stall (60 s without data) before that is retried. The final failure is classified as `UpdateFailure`: `serverUnavailable` (5xx, 429, timeouts, dropped or refused connections), `offline` (not connected, name lookup failed, cellular data off), `verification` (signature, notarization, identity, version, older than running) or `other`; it is carried in `UpdateRowState.failed(_, reason:)` (decision 72's states). General shows the reason under "The update failed." ("GitHub isn’t responding. Try again in a few minutes.", "You appear to be offline.", "The downloaded update couldn’t be verified, so it wasn’t installed."), and the manual check's "Couldn’t check for updates" alert uses the same words for the first two. The menu row stays "Update Failed — Try Again"; its tooltip and accessibility label add the reason. Location problems still open the release page (unchanged). Automatic checks keep their 1 h backoff after a final failure. Cost: up to three requests are sent instead of one, and a failure takes longer to report. With quick failures (5xx, refused connection, offline) that is about 7 s more; with two `Retry-After: 30` answers about 60 s. A check that times out each time takes up to about 52 s (3 × 15 s plus the waits), during which the manual check's alert waits and Check for Updates… and Check Now stay disabled (a manual check is not started while an automatic one runs). A download that stalls each time shows Downloading for up to about 3 min (3 × 60 s plus the waits); in the unlikely case that every try runs nearly to the 600 s limit before stalling, up to about 30 min.
88. **Styled disk image window and a macOS 26 style icon.** The release disk image carries a background picture (`Resources/dmg/background.tiff`, 1x and 2x) and Finder view settings (`Resources/dmg/DS_Store`, recorded once with `scripts/make-dmg-layout.sh`), on an HFS+ volume named `trrek`, built by `scripts/make-dmg.sh`; this replaces the plain `diskutil image create` image of decision 46's era, since the recorded settings find the background on a volume like the one they were made on. The icon is drawn by `scripts/render-icon.swift` as a static image in the macOS 26 style (rounded square on the standard grid, depth, glass, light); the system's dynamic layered icons need a compiled icon asset that this project, built without Xcode, does not produce. Cost: changing the window layout means recording the view settings again on a Mac, with Finder automation allowed once.
