# Phase 3 (v0.3.0) Implementation Plan

> **For agents:** implement task by task with superpowers:subagent-driven-development. Tasks 1 and 2 separate cleanly by file and run in parallel worktrees; Task 3 starts after both are merged.

**Goal:** A selectable action for each edge, new edge and corner actions, slide sensitivity, export/import of settings as a `.trrek` file, and a Turkish interface with a language picker.

**Architecture:** The engine extends the action list, and step distances are scaled by a sensitivity multiplier. New actions are sent through `CommandDispatcher` using the existing ports (key, media key, app launch). Export/import is a pure encoder in `TrrekAppCore`, with a panel and a file-open handler on the app side. Localization uses `.lproj/Localizable.strings` files; the language picker writes the app's `AppleLanguages` preference and asks for a relaunch.

**Technology:** Swift 6, SPM, SwiftUI (Liquid Glass), AppKit, Swift Testing.

**Spec:** `docs/superpowers/specs/2026-11-03-trrek-design.md` (this plan extends sections 5 and 7; the tasks write a short addendum section to the spec).

## Global constraints
- The `CLAUDE.md` rules apply: no other app/library names; Swift 6.2 / macOS 26 SDK; no `@State`; no per-frame heap allocation; no periodic timers; private symbols only in `PrivateSymbols.swift`.
- Source strings stay in English; Turkish comes with the localization file.
- The settings schema stays backward compatible through the forgiving decoder; old settings files (e.g. `swapSides`) are migrated correctly.
- The rule that only the keyboard backlight works without the Accessibility permission applies to the new actions too.
- Every task ends with `make check` green, a `CHANGELOG.md` Unreleased line, `docs/testing.md` items if needed, and `docs/decisions.md` decisions.

## Review focus
1. An old settings file (`swapSides: true`) must open in the new version as left=volume, right=brightness.
2. When a corrupt, empty, differently formatted, or newer-schema `.trrek` file is imported, the app does not crash, the current settings do not change, and the user gets a clear warning.
3. On a vertical edge (left/right), for actions such as switching apps or tabs, up = next, down = previous.
4. Even with sensitivity at the extreme, the step distance stays above the engine's tolerance threshold; the boundary haptic rule is not broken.
5. With Turkish selected, no interface text stays in English; format specifiers (`%@`, `%d`) are the same in both languages.

### Task 1: Edge and corner actions, sensitivity

**Edge actions** (same list on all four edges): `volume`, `brightness`, `keyboardBacklight`, `switchApps`, `switchTabs`, `switchDesktops`, `scrubVideo`, `media`, `zoom`, `undoRedo`, `off`.
- `switchTabs`: ⌃⇥ (forward) / ⌃⇧⇥ (back) per step; no commit needed. Step 12 mm.
- `switchDesktops`: ⌃→ / ⌃←. Step 20 mm.
- `zoom`: ⌘= / ⌘−. Step 8 mm.
- `undoRedo`: forward ⇧⌘Z, back ⌘Z. Step 10 mm.
- Direction rule: on a horizontal edge right, on a vertical edge up = forward/increase.
- `Settings`: `leftEdge` (default `brightness`), `rightEdge` (default `volume`). `swapSides` is no longer written; when read, if `true` it is migrated as left=`volume`, right=`brightness`. The Swap Sides switch in the Edges tab goes away, replaced by left and right edge pickers. The diagram shows all four edges.
- When the keyboard backlight bridge is missing, `keyboardBacklight` falls back to `media` on every edge (the current rule generalized to all edges).

**Corner actions:** in addition to the existing `off`, `mute`, `screenshot`: `playPause`, `missionControl`, `appWindows`, `showDesktop`, `spotlight`, `lockScreen`, `screenshotArea`.
- Mission Control, app windows and show desktop work by opening the system's Mission Control app with an argument (none, `2`, `1`); they do not depend on keyboard shortcut settings. If the app cannot be found, the error is logged, no crash.
- `spotlight` ⌘Space, `lockScreen` ⌃⌘Q, `screenshotArea` ⇧⌘4, `playPause` media play/pause.

**Sensitivity:** `Settings.slideSensitivity` (`veryLow`, `low`, `standard`, `high`, `veryHigh`; default `standard`). The multipliers are 1.6, 1.25, 1.0, 0.8, 0.6 respectively; `ConfigMapper` scales all step distances (`stepMM`, `appSwitchStepMM`, `scrubStepMM`, `mediaSkipStepMM` and the distances of the new actions) by this multiplier. A "Slide Sensitivity" picker in the General tab.

**Tests:** for each new edge action, a synthetic frame test on a horizontal and a vertical edge (correct command, correct direction); for each new corner action, double tap → command; a test with fake ports that the dispatcher turns each new command into the correct key/app call; a `swapSides` migration test; a sensitivity multiplier test; a test that the new actions are `off` when accessibility is off.

### Task 2: Export and import of settings (`.trrek`)

- `SettingsDocument` in `TrrekAppCore`: `encode(_ settings: Settings) -> Data` and `decode(_ data: Data) throws(SettingsDocumentError) -> Settings`. The file is JSON, indented with sorted keys: `{"format": "trrek-settings", "formatVersion": 1, "appVersion": "<Version.string>", "settings": {…}}`. `launchAtLogin` and `welcomeShown` are not exported; on import their current values are kept.
- Errors: `notSettingsFile` (not JSON or a different `format`), `newerFormat` (`formatVersion` > 1). The contents of `settings` are read with the forgiving decoder; unknown fields fall back to the default.
- "Export Settings…" and "Import Settings…" buttons in the General tab. The panels are attached to the settings window as sheets (`SettingsModel.window`). Default file name `trrek Settings.trrek`.
- Confirmation before import: "Replace your current settings with the ones in “<file>”?" (Replace / Cancel). On error, a descriptive warning; the settings do not change.
- `Info.plist.in`: `com.burakseyitkara.trrek.settings` via `UTExportedTypeDeclarations` (extension `trrek`, conforms to `public.json`) and `CFBundleDocumentTypes` (role Viewer). Double-clicking a `.trrek` file in Finder opens trrek (or brings it to the front), opens the settings window, and imports with the same confirmation (`application(_:open:)`).
- **Tests:** round trip (encode → decode equal, except `launchAtLogin`/`welcomeShown`); corrupt data, empty data, wrong `format`, newer `formatVersion`; an unknown action name falls back to the default; file name extension.

### Task 3: Language picker and Turkish interface (after Tasks 1 and 2)

- `Sources/Trrek/Resources/en.lproj/Localizable.strings` and `tr.lproj/Localizable.strings`; `build-app.sh` puts them in the bundle's `Resources` folder. `Info.plist.in`: `CFBundleDevelopmentRegion` `en`, `CFBundleLocalizations` `[en, tr]`.
- All user-visible text is localized: menu, settings tabs, welcome window, overlay, warnings, panel titles, `TrrekAppCore` labels (`SettingsLabels`, `StatusText`, `WelcomeContent`, `OverlayContent`). Library code reads from `Bundle.main`.
- `Settings.language` (`system`, `english`, `turkish`; default `system`). A "Language" picker in the General tab. On change, the app's `AppleLanguages` preference is written (deleted for `system`) and the message "Relaunch trrek to use the new language." appears with a "Relaunch" button; relaunching quits the app and reopens the same bundle.
- **Tests:** the key sets in the two files are the same; for each key the format specifiers are the same; every English key used in source with `Text("…")`/`String(localized:)` exists in the `en` file (a simple scan test or script); the language preference write/delete logic is tested as a pure function.
- The language rule in `CLAUDE.md` gets "The interface is written in English, its Turkish translation comes with `tr.lproj`". The README is updated.
